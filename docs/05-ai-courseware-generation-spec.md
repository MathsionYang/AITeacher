# AI 课件生成规范

## 1. 目标

课件生成只基于每个章节的客观知识点、知识点来源和自建教学模板。大模型负责把结构化知识点转成课堂表达、图形化讲解、动画脚本和例题讲解思路，但不作为事实来源，也不直接复述教材原文、搬运教材图片或复制教材例题。

MVP 阶段先在本地前端用确定性模板和 AI 生成视觉化课件。知识点课件区域默认空白，支持 AI 生成/重新生成、生成中进度动画、完成后一次性展示、人工审核修改、保存审核稿、JSON 导入导出、导出 Markdown 和通过浏览器打印导出 PDF。后续接入大模型时，仍保持“结构化输入、稳定模板、人工审核、可追溯来源”的流程。

## 2. 输入数据

每次生成课件必须使用以下结构化输入：

- 教材范围：版本、学科、年级、册别、单元。
- 客观知识点：来自 `knowledge/rj-grade{n}-math-{volume}.js` 的 `points`、`tags`、`summary`。
- 来源索引：来自 `data.js` 的 `sourceCatalog` 和单元 `sourceIds`。
- 模板版本：例如 `courseware_template_v1`，用于保证同一输入在同一模板下输出大致一致。
- 人工审核稿：默认不自动展示模板课件，只有 AI 生成、人工保存或导入历史 JSON 后才展示审核稿。

教材 PDF 或人工整理文档只用于提炼客观知识点和校验范围，不进入最终课件输出，不保存原文段落、课本插图或原题。

## 3. 稳定生成规则

为了避免课件每次生成差异过大，生成流程必须遵守：

- 固定课件骨架：学习目标、情境导入、概念讲解、例题精讲、课堂练习、小结与作业。
- 固定视觉模板：按知识点标签选择分数图、几何图、统计图、数轴图、流程图、情境图解、练习阶梯图等。
- 固定种子：使用 `version + grade + volume + unitId + templateVersion + knowledgeHash` 作为生成种子。
- 低随机性：大模型参数使用低 temperature；同一输入不主动改写标题、页数和核心讲解顺序。
- JSON Schema 输出：模型只输出结构化字段，不直接生成自由散文。
- 内容缓存：保存 `inputHash`、`modelVersion`、`templateVersion` 和审核状态；输入不变时复用上次结果。

推荐输出结构：

```json
{
  "unitId": "grade5-a-unit1",
  "templateVersion": "courseware_template_v1",
  "slides": [
    {
      "title": "学习目标",
      "visualType": "goals",
      "body": "一句话说明本页目标",
      "bullets": ["客观知识点 1", "客观知识点 2"],
      "sourceIds": ["rj-textbook-local", "math-curriculum-standard"]
    }
  ]
}
```

## 4. 视觉优先原则

课件不能变成大段文字稿。图形化的目的不是好看，而是帮助学生理解知识点、数量关系、公式来源、步骤顺序和错因。每页必须先有教学解释图，再用少量文字辅助说明：

- 每页至少一个图形区，优先使用图、表、数轴、流程、面积模型、数量关系图、统计图。
- 情境导入和例题精讲优先使用“物品/数量/分组/线段条”等图解表达，例如购物题画出 3 个笔记本和 1 支钢笔，剩余平均分题画出总量、已完成、剩余和 4 人分组。
- 每个图形都必须回答一个明确问题，例如“整体如何等分”“长和宽如何对应面积公式”“数据之间如何比较”“先找什么再列式”。
- 文本控制在短句和要点，避免整页密集段落。
- 动画只服务理解，例如分数格逐步填充、数轴标点移动、统计柱增长、解题流程逐步显现；不做与知识点无关的装饰动画。
- 视觉模板由程序确定，大模型只给“图形意图”和必要参数，不生成不稳定的随意插图。
- 涉及教材中的图形时，只重画原创示意图，不复刻教材版式、人物、插图和例题。

## 5. 人工审核工作流

课件必须支持人工审核修改，推荐状态流：

```text
生成初稿 -> 教师/教研审核 -> 保存审核稿 -> 发布/导出 -> 后续可重置或再审核
```

审核项：

- 知识点是否客观、准确、覆盖本单元核心范围。
- 每页来源是否指向可信来源。
- 例题是否原创，且只考查当前知识点。
- 同一题型是否重复过多。
- 解析是否包含审题、建模、计算、作答、易错点和检查方法。
- 是否存在教材原文、课本图片、原题或教辅题库痕迹。

MVP 当前把审核稿保存在浏览器 `localStorage` 中。产品化后可改为本地 JSON 文件或 SQLite 数据库，仍不需要服务器。

当前 UI 中，AI 生成课件入口放在“知识点课件”页面内；生成过程展示进度动画，不提前展示半成品内容，完成模型返回、字段补齐和来源绑定后再进入可审核课件稿。导出 JSON 用于本地备份、人工审核流转和迁移；导入 JSON 会优先恢复文件中的年级、册别和单元，再写入对应单元的审核稿。

## 6. 大模型与 Agent 分工

大模型和 Agent 适合放在这些环节：

- 课件编排 Agent：把单元知识点映射到固定课件骨架，生成每页标题、短句讲解和视觉意图。
- 图形表达 Agent：把知识点转成图形参数，例如分数格、数轴刻度、几何形状、统计柱、物品数量、总量条和分组图。
- 同步出题 Agent：围绕知识点生成少量原创客观题，限定选择题、填空题、计算填空题、单位换算填空题和数据填空题，控制题型覆盖和重复度。
- 解析 Agent：生成详细解析步骤、易错提醒和检查方法。
- 质检 Agent：检查知识点覆盖、来源缺失、客观题型、开放题过滤、答案一致性和版权风险。
- 审核合并 Agent：保留教师人工修改，把新生成内容与审核稿做差异对比。

不建议让大模型独立决定教材范围或直接读取网络教材后自由生成。教材范围应先由结构化知识库锁定，再让模型在边界内表达。

模型调用参考 OfferAgent 的 OpenAI-compatible 配置方式：`temperature` 固定为 0，使用固定 `seed`，输出 JSON，再由规则引擎检查知识点覆盖、来源完整性、客观题型、开放题过滤、题型重复和版权风险。更完整的模型/Agent/规则边界见 `docs/06-llm-agent-architecture.md`。

## 7. 导出

MVP 支持三类导入导出：

- JSON：用于审核稿备份、人工修改、迁移和后续本地文件存储。
- Markdown：用于教研二次编辑和版本管理。
- PDF：通过浏览器打印功能导出，打印样式只保留课件页、视觉图形和来源说明。

后续如果需要 PPTX，可在本地客户端内把同一份 JSON 课件渲染为幻灯片文件，不改变生成规则。

## 8. 验收标准

- 同一单元、同一模板版本下，重复生成的页数、标题、知识点顺序和视觉类型基本一致。
- 每页课件都带来源说明。
- 教师可以在本地修改课件，并保存审核稿。
- 课件审核稿可以导出为 JSON，并能导入回对应单元继续编辑。
- 审核稿可覆盖当前展示结果，并能清空后重新生成或重新导入。
- 导出 PDF 后页面中保留图形化讲解，而不是纯文本大纲。
- 情境导入和例题精讲能看到帮助理解数量关系的图形，而不是只显示大段文字。
- 课件和题目不包含教材原文、教材插图、教材原题或未经授权题库内容。
