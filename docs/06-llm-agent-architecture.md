# 大模型与 Agent 架构设计

## 1. 设计原则

参考 `D:\OfferAgent` 的模型配置方式，AITeacher 采用 OpenAI-compatible Chat Completions 接口作为通用模型协议，支持 provider、model、apiKey、baseUrl、timeout、temperature 和 seed 配置。

大模型和 Agent 不替代整个系统，只放在“需要理解、生成、诊断、规划”的环节。判分、题库、来源、权限、缓存、审核状态和版权校验尽量规则化、结构化、可追踪。

核心边界：

- 模型负责：生成、解释、归因、计划、语义理解。
- Agent 负责：多步骤调度、工具调用、结果检查、失败重试。
- 规则引擎负责：确定性判分、题型分布、答案验算、来源绑定、权限和合规。
- 人工审核负责：最终课件、题目和开放题评分规则的发布确认。

## 2. 模型配置

本项目新增 `.env.example`，字段与 OfferAgent 的配置思路保持一致：

```text
LLM_PROVIDER=openai
LLM_MODEL=
LLM_TEMPERATURE=0
LLM_SEED=20260713
LLM_TIMEOUT_MS=90000
OPENAI_API_KEY=
DEEPSEEK_API_KEY=
QWEN_API_KEY=
KIMI_API_KEY=
CUSTOM_LLM_BASE_URL=
CUSTOM_LLM_API_KEY=
LOCAL_LLM_PROXY_BASE_URL=
```

运行策略：

- MVP 无需真实模型即可运行，默认走本地模板和规则。
- 真实模型调用使用 OpenAI-compatible `/chat/completions`。
- 同一输入尽量使用 `temperature: 0` 和固定 `seed`，减少课件和题目漂移。
- API Key 不写入仓库，不放入可提交代码，不建议持久化到浏览器 `localStorage`。
- 浏览器直连失败时，可使用客户电脑上的本地代理或客户自有模型网关。
- OCR 与 LLM 分离：OCR 识别文字/数字，LLM 理解过程和错因。

## 3. 大模型适用环节

### 课件生成

输入：

- 教材版本、年级、册别、单元。
- 已审核的客观知识点。
- 来源说明。
- 教学目标。

输出：

- 课件大纲。
- 讲解话术。
- 原创例题。
- 课堂互动。
- 小结和作业。
- 图形化表达建议。

限制：

- 不能让模型直接“编教材内容”。
- 不能复述教材原文、复制课本图片或搬运教材例题。
- 必须基于已审核知识点生成原创讲解。

### 题目生成

输入：

- 知识点。
- 题型。
- 难度。
- 题量。
- 避免重复题型要求。

输出：

- 原创题。
- 答案。
- 解析。
- 评分点。

后置校验：

- 答案可计算。
- 难度匹配。
- 题型不重复。
- 来源和知识点绑定完整。
- 版权相似度检查通过。

### 详细解析

输入：

- 题目。
- 标准答案。
- 学生答案。
- 知识点。

输出：

- 审题思路。
- 关键步骤。
- 错因。
- 易错点。
- 同类提醒。
- 检查方法。

这是最适合大模型发挥体验价值的环节，但结论仍应受到标准答案和评分规则约束。

### 错因诊断

输入：

- 学生答案。
- 正确答案。
- 历史错题。
- 对应知识点。

输出：

- 计算错误。
- 概念不清。
- 审题错误。
- 单位遗漏。
- 步骤缺失。
- 知识点混淆。

错因分类优先用固定枚举，大模型负责把学生表现解释得更清楚。

### 个性化复习计划

输入：

- 错题。
- 知识点掌握率。
- 最近练习结果。
- 周期测验设置。

输出：

- 下次练什么。
- 练多少题。
- 先复习哪个知识点。
- 错题占比多少。
- 是否需要回到课件重学。

### 拍照批改后的语义理解

OCR 负责识别文字、数字、算式和题号。模型负责理解“学生到底写了什么、过程错在哪”。

适用场景：

- 应用题。
- 过程题。
- 草稿不规范的口算或竖式。
- 单位、答句、步骤遗漏。

客观题和结果明确的计算题仍优先走规则判分。

## 4. Agent 适用环节

Agent 是“任务调度员 + 检查员 + 多步骤执行器”，不直接取代业务模块。

### 课件 Agent

流程：

```text
读取教材范围
  -> 查知识点来源
  -> 调模型生成课件 JSON
  -> 检查知识点覆盖
  -> 检查来源完整性
  -> 检查疑似教材原文/原题
  -> 输出可编辑课件
  -> 等待人工审核
```

### 出题 Agent

流程：

```text
按知识点拆题量
  -> 控制题型分布
  -> 调模型生成候选题
  -> 规则引擎验算答案
  -> 校验难度和题型重复
  -> 相似度检测
  -> 不合格则重生成
  -> 输出合格题组
```

### 批改 Agent

流程：

```text
接收图片
  -> 调 OCR
  -> 结构化题号和答案
  -> 规则判分
  -> 对过程题调模型解释
  -> 生成逐题解析
  -> 写入错题库
```

### 错题复习 Agent

流程：

```text
分析错题库
  -> 找薄弱知识点
  -> 生成错题卷
  -> 安排间隔复习
  -> 更新掌握状态
```

### 周期测验 Agent

流程：

```text
读取测验计划
  -> 到时间自动组卷
  -> 混合新题和错题
  -> 控制难度
  -> 生成测验后等待提交
  -> 提交后更新学情报告
```

## 5. 规则化模块

以下模块不应交给大模型自由决定：

- 教材版本、年级、册别、单元和知识点来源。
- 题库入库状态和审核状态。
- 客观题、填空题、计算题的标准答案判定。
- 题目分值、题量、难度上限和题型分布。
- 错题去重、错题状态、复习间隔。
- 用户权限、API Key 安全、文件访问边界。
- 版权相似度、教材原文检测、来源完整性校验。

## 6. 建议本地模块

后续本地客户端可以按以下模块拆分：

```text
model-client
  OpenAI-compatible 调用、流式读取、连接测试、错误归因

agent-orchestrator
  课件、出题、批改、错题复习、周期测验 Agent 编排

rule-engine
  判分、答案验算、题型分布、难度校验、来源校验

content-store
  知识点包、课件审核稿、题目、错题库、成绩记录、测验记录

ocr-adapter
  本地 OCR 或客户自有 OCR 接口

exporter
  Markdown、PDF、后续 PPTX

mock-data
  可替换测试数据，覆盖初始范围、错题、成绩趋势、周期测验设置
```

## 7. 验收标准

- 未配置模型时，MVP 仍能使用本地模板完成课件、出题、判分和错题流程。
- 配置模型后，只有生成、解析、诊断、规划环节调用模型。
- 同一输入在同一 seed 和模板版本下输出大致稳定。
- 每个模型输出都必须经过规则校验或人工审核后进入正式内容库。
- 判分、来源、权限、版权风险不依赖模型自由判断。
