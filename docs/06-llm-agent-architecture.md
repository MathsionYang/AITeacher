# 大模型与 Agent 架构设计

## 1. 基本原则

大模型和 Agent 不替代整个系统，只放在需要理解、生成、诊断、规划的环节。

规则化部分由本地代码完成：

- 权限与教师登录状态
- 年级/册别/单元范围
- 同步出题题量固定 10；周期测验题量 10-100
- 总分 100
- 单元边界
- 题型过滤
- 答案可判定性校验
- 审核状态
- 导出版本号

## 2. 模型配置

参考 OfferAgent 的 OpenAI-compatible 配置方式：

- provider
- model
- baseUrl
- apiKey
- temperature
- seed
- timeoutMs

推荐使用本地代理，页面不保存真实 Key。系统设置中只持久化 provider、model、baseUrl，不持久化页面临时 API Key。

## 3. 课件 Agent

输入：

- 教材版本、学科、年级、册别、单元
- 当前单元客观知识点
- 来源说明
- 教学目标
- 本地模板课件

输出：

- MarkdownFlow 导学结构
- 图形化表达建议
- 讲解文本
- 导学追问
- 小测与复盘

约束：

- 不复制教材原文、课本例题和商业题库内容。
- 不越过当前单元知识点边界。
- 课件结构保持稳定，便于教师审核和复用。

## 4. 出题 Agent

输入：

- 当前单元知识点
- 难度
- 同步出题固定题量 10；周期测验使用教师设置的 10-100 题
- 题型要求
- 禁止跨单元

输出：

- 原创题
- 标准答案
- 分值
- 知识点标签
- 必要的教师审核提示

后置校验：

- 当前单元边界
- 全知识点覆盖
- 题型不过度重复
- 只保留选择题、填空题等标准答案题
- 开放题过滤
- 总分归一为 100
- 教师人工审核后再导出试题

## 5. PPT 制作 Agent

输入：

- 已审核课件
- 单元知识点
- 图形化表达

输出：

- PPT 页结构
- 版式建议
- 每页标题、主体、图形、讲解顺序

实际 PPTX 文件由 `pptx-exporter.js` 在本地生成。

## 6. OCR 与校正扩展

当前 MVP 不开放 OCR、学生作答、自动判分和错题解析。后续如重新开放：

- OCR 负责识别题号、文字、数字、算式。
- 模型负责理解答案语义和错因。
- 规则引擎负责判分和答案等价判定。

## 7. Agent 编排

```text
课件生成
  -> 读取当前单元知识点
  -> 调用课件 Agent
  -> 结构化 normalize
  -> 人工审核
  -> 导出 PDF/PPTX/JSON

同步出题
  -> 读取当前单元知识点
  -> 调用出题 Agent
  -> 规则引擎校验
  -> 不合格则丢弃或补题
  -> 教师人工审核
  -> 保存生成记录
  -> 导出空白卷/含答案 PDF

周期测验
  -> 读取当前单元知识点
  -> 规则引擎生成/校验
  -> 按教师设置生成 10-100 题并避开已有题干
  -> 保存 scheduled_paper 记录
  -> 导出 PDF
```
